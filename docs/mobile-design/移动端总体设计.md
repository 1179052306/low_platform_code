# 移动端页面设计与 Flutter 渲染引擎总体设计

> 日期：2026-11-03
> 范围：移动端低代码页面设计器扩展 + Flutter 运行时渲染引擎 + Android 壳工程 + APK 打包

---

## 1. 总体架构

```
┌─────────────────────────────────────────────────────────┐
│  现有 Vue 低代码设计器 (web-code)                        │
│  └─ 新增 pageType=mobile 模式                           │
│     ├─ 复用表单控件体系 (text-box/select/date/...)       │
│     ├─ 新增移动端专属控件 (app-bar/bottom-nav/list...)   │
│     ├─ 移动端画布 (手机外壳预览 375×812)                │
│     └─ 保存 → POST /api/lowcode/page (schema JSON)      │
├─────────────────────────────────────────────────────────┤
│  后端 (bcd-code 3015 / gateway 7000)                    │
│  └─ schema 存 lc_page_schema 表 (无改动，复用现有存储)   │
│     └─ GET /api/lowcode/page/schema?code=xxx 返回 JSON   │
├─────────────────────────────────────────────────────────┤
│  Flutter App (mobile-app/)                              │
│  ├─ 启动 → 拉 schema JSON (默认 http://<本机IP>:7000)    │
│  ├─ SchemaRenderer: JSON → Widget 树 (运行时动态构建)    │
│  ├─ WidgetFactory: 按 type 分发到各控件渲染器            │
│  └─ 控件库 (5 类 20+ 控件)                              │
└─────────────────────────────────────────────────────────┘
```

**核心数据流**：设计器画页面 → 保存 schema JSON 到后端 → Flutter App 启动/切页面时拉 schema → SchemaRenderer 递归构建 Widget 树 → 渲染。

### 2.2 金蝶苍穹/用友做法参考

- **金蝶苍穹零代码**：同一设计器多端预览（PC/移动/Pad），设计时一套 schema，移动端控件映射 Web 控件（如 data-grid → list-view，checkbox → switch）。页面骨架用 Scaffold（AppBar+Body+BottomNav），符合移动端习惯。
- **用友 YonBuilder**：同样一套 schema 多端，移动端强调列表+卡片+底部导航，表单控件自适应小屏（label 上移、输入框全宽）。
- **共同点**：不为移动端单独造控件，而是 Web 控件的移动端渲染适配 + 少量移动端专属控件（导航/手势类）。

### 2.3 移动端布局规则

| 规则 | 说明 |
|------|------|
| 画布尺寸 | 375×812（iPhone 13 逻辑分辨率），设计时手机外壳预览 |
| label 位置 | 默认 top（上标签），输入框全宽 |
| 控件间距 | 默认 16px |
| 表单控件默认高度 | 48px（移动端触控友好，比 Web 的 36px 大） |
| 列表项高度 | 最小 56px（Material Design 触控目标） |
| 底部安全区 | 自动 padding-bottom 避开手势条 |

## 3. Schema 结构（与现有设计器一致，移动端扩展）

```json
{
  "pageType": "mobile",
  "pageCode": "m_item_list",
  "pageName": "物料列表",
  "root": {
    "type": "scaffold",
    "props": {
      "title": "物料列表",
      "appBarColor": "#1976D2"
    },
    "children": [
      {
        "type": "list-view",
        "props": {
          "bizCode": "B_ITEM",
          "primaryKey": "item_key",
          "columns": [
            {"field": "item_code", "label": "物料编码"},
            {"field": "item_name", "label": "物料名称"}
          ],
          "onRowTap": {"action": "openPage", "pageCode": "m_item_form", "mode": "edit"}
        }
      }
    ],
    "bottomNav": {
      "type": "bottom-nav",
      "props": {
        "items": [
          {"label": "首页", "icon": "home", "pageCode": "m_home"},
          {"label": "我的", "icon": "person", "pageCode": "m_profile"}
        ]
      }
    },
    "fab": {
      "type": "floating-action-button",
      "props": {"icon": "add", "onTap": {"action": "openPage", "pageCode": "m_item_form", "mode": "new"}}
    }
  }
}
```

**与现有 schema 的关系**：`pageType` 字段区分 web/mobile，`root` 结构与 Web 端一致（type+props+children），Flutter 渲染器和 Web RendererNode 各自按 type 分发。后端存储/网关/CRUD 完全复用，无改动。

## 4. Flutter 渲染引擎设计

### 4.1 核心流程

```
App 启动
  → AppConfig 加载默认 baseUrl (http://<本机LAN IP>:7000)
  → SchemaFetcher.fetch(pageCode) → GET {baseUrl}/api/lowcode/page/schema?code=xxx
  → SchemaRenderer.render(schema.root)
      → WidgetFactory.build(node)
          → switch(node.type) 分发到具体控件渲染器
          → 递归 render(node.children)
      → 返回 Widget 树
  → MaterialApp 渲染
```

### 4.2 WidgetFactory 分发

```dart
Widget build(Node node, BuildContext ctx, Map<String,dynamic> formData) {
  return switch (node.type) {
    'scaffold'    => ScaffoldWidget(node).build(ctx, formData),
    'column'      => ColumnWidget(node).build(ctx, formData),
    'row'         => RowWidget(node).build(ctx, formData),
    'text-box'    => TextBoxWidget(node).build(ctx, formData),
    'select'      => SelectWidget(node).build(ctx, formData),
    'list-view'   => ListViewWidget(node).build(ctx, formData),
    'button'      => ButtonWidget(node).build(ctx, formData),
    // ... 20+ 控件
    _             => Text('未知控件: ${node.type}'),
  };
}
```

### 4.3 数据绑定

- **表单数据**：`formData` Map 在表单页面内维护，控件 onChange 更新 formData[field]。
- **列表数据**：list-view 控件自行调网关 `POST {baseUrl}/api/lowcode/crud/{bizCode}/query` 拉数据，分页加载。
- **事件动作**：`onTap`/`onRowTap` 的 `action=openPage` → 路由跳转拉新 schema 渲染；`action=submit` → 调网关保存。

### 4.4 路由

Flutter Navigator 2.0，每个 pageCode 是一个路由，onGenerateRoute 时拉对应 schema 渲染。

## 5. Android 壳工程

- **形式**：纯 Flutter 工程 (`flutter create mobile_app`)
- **包名**：`com.lowcode.mobile`
- **最低 SDK**：minSdkVersion 21（Android 5.0，覆盖 95%+ 设备）
- **网络权限**：`INTERNET` + `ACCESS_NETWORK_STATE`
- **明文 HTTP**：`android:usesCleartextTraffic="true"`（开发期连本机 HTTP 需要，生产 HTTPS 不需要）
- **默认 baseUrl**：启动时取本机 LAN IP（通过 WiFi/以太网），拼 `http://<IP>:7000`。提供设置页可手动改。
