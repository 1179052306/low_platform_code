## 5. 核心模块设计

### 5.1 LayoutService — 布局管理

```java
public class LayoutService {
    /** 获取完整布局（一次查询拼装所有层级） */
    WarehouseLayoutDTO getLayout(Long warehouseId);
    
    /** 保存布局（全量覆盖 + 自动创建快照） */
    void saveLayout(Long warehouseId, WarehouseLayoutDTO layout, String changeLog, String operator);
    
    /** 批量更新库位状态（WebSocket 推送触发） */
    void updateLocationStatus(Long warehouseId, List<LocationStatusUpdate> updates);
}
```

**查询优化：**
- 仓库 → 库区 → 货架 → 库位 一次性批量查询，Java 内存中拼装树结构
- 库位查询用 `WHERE warehouse_id = ? ORDER BY rack_id, level, bay`，利用索引
- 万级库位查询分页：`LIMIT 10000 OFFSET 0`，前端按需加载

### 5.2 PickingPathService — 拣货路径计算

```java
public class PickingPathService {
    /** 计算拣货路径 */
    PickingPathDTO calculatePath(PathRequest req);
}
```

**算法实现：**

#### NearestNeighborAlgorithm（最近邻启发式）
1. 从起点出发
2. 每次选择距离当前位置最近的未访问库位
3. 重复直到所有库位访问完
4. 返回到终点（或起点）
- 时间复杂度 O(n²)，适合 n < 100

#### SShapeAlgorithm（S 形遍历）
1. 将库位按通道分组
2. 按通道顺序 S 形穿梭遍历
3. 同通道内按位置顺序访问
- 适合规则货架布局，效率高

#### TSPSolver（最优解）
1. n ≤ 10：精确 DP（Held-Karp）O(n²·2ⁿ)
2. n ≤ 20：分支限界
3. n > 20：2-opt 改进最近邻解
4. 通道约束：路径必须沿通道行走，不能穿越货架

**通道约束路径：**
- 构建 `ChannelGraph`：通道为边，交叉点为节点
- 库位到通道的接入点：库位最近通道边
- 实际路径 = 通道图上的最短路径（Dijkstra/A*）
- TSP 在通道节点层面求解，库位访问顺序嵌入通道路径

### 5.3 LocationRecommendService — 库位推荐

```java
public class LocationRecommendService {
    List<LocationRecommendDTO> recommend(RecommendRequest req);
}
```

**推荐策略：**

| 策略 | 评分规则 |
|---|---|
| distance | 距离收货区/出库口越近分越高 |
| utilization | 优先推荐空库位（utilization=0），其次部分占用 |
| category | 同品类集中存放，查找同品类所在库区优先推荐 |

评分公式：`score = w1 * distanceScore + w2 * utilizationScore + w3 * categoryScore`（权重可配）

### 5.4 EditLockService — 编辑锁（Redis）

```java
public class EditLockService {
    /** 获取锁 */
    EditLock acquire(Long warehouseId, String userId, String userName);
    
    /** 释放锁 */
    void release(Long warehouseId, String userId);
    
    /** 查询锁状态 */
    EditLock getStatus(Long warehouseId);
    
    /** 强制释放 */
    void forceRelease(Long warehouseId, String operator);
    
    /** 续期（编辑中定时续期防过期） */
    void renew(Long warehouseId, String userId);
}
```

**Redis 实现：**
- Key: `w3d:editlock:{warehouseId}`
- Value: JSON `{userId, userName, lockedAt, expiresAt}`
- TTL: 30 分钟（编辑中前端每 5 分钟续期）
- 获取锁：`SET key value NX EX 1800`（原子操作）
- 强制释放：管理员权限检查后 `DEL key`

### 5.5 SnapshotService — 版本管理

```java
public class SnapshotService {
    /** 创建快照 */
    Long createSnapshot(Long warehouseId, String description, String operator);
    
    /** 回滚 */
    WarehouseLayoutDTO rollback(Long warehouseId, Long snapshotId, String operator);
```

- 保存布局时自动创建快照（无需手动）

- 回滚 = 加载快照数据 → 覆盖当前布局表 → 创建回滚快照
- 版本号自增：`MAX(version) + 1`

### 5.6 W3DWebSocketHandler — WebSocket 推送

```java
@Component
public class W3DWebSocketHandler extends TextWebSocketHandler {
    /** 连接建立 */
    void afterConnectionEstablished(WebSocketSession session);
    
    /** 消息处理（心跳 ping/pong） */
    void handleTextMessage(WebSocketSession session, TextMessage message);
    
    /** 连接关闭 */
    void afterConnectionClosed(WebSocketSession session, CloseStatus status);

```

**推送消息类型：**

| type | 触发时机 | payload |
|---|---|---|
| locationStatus | 库位状态变更（WMS/人工） | `[{locationId, status, utilization, productCode}]` |
| lockChanged | 编辑锁获取/释放 | `{lockedBy, action}` |
| layoutUpdated | 布局保存 | `{version, operator}` |
| snapshotCreated | 快照创建 | `{snapshotId, version}` |

**连接路径：** `/ws/warehouse-3d/{warehouseId}`
**会话管理：** `ConcurrentHashMap<Long, Set<WebSocketSession>>` 按 warehouseId 分组
**心跳：** 前端 30s ping，后端 pong；60s 无心跳则关闭会话

### 5.7 ChannelTopologyService — 通道拓扑

```java
public class ChannelTopologyService {
    /** 构建通道图 */
    ChannelGraph buildGraph(Long warehouseId);
    
    /** 两点间最短路径（沿通道） */
    List<Point> shortestPath(ChannelGraph graph, Point from, Point to);
}
```

- 通道图节点：通道交叉点 + 库位接入点
- 通道图边：通道段，权重 = 实际距离
- 最短路径：Dijkstra（库位数 < 1000）或 A*（带启发式，大规模）

## 6. 性能优化

| 场景 | 策略 |
|---|---|
| 万级库位查询 | 批量查询 + 索引 `idx_location_warehouse` |
| 布局保存 | 事务内全量删除+插入（平库数据量可控）或 diff 更新 |
| 路径计算 | n ≤ 20 精确解，n > 20 启发式 + 2-opt |
| 库位状态推送 | 增量推送（仅变更库位），非全量 |
| 快照存储 | JSON 压缩（GZIP）后存 text 字段 |
| 编辑锁 | Redis 原子操作，无 DB 压力 |
| 通道图构建 | 按 warehouseId 缓存到 Redis（TTL 10min），布局变更时失效 |

## 7. 异常处理

| 异常 | 处理 |
|---|---|
| 编辑锁被他人持有 | 返回 409 + 锁持有者信息 |
| 布局数据校验失败 | 返回 400 + 字段级错误信息 |
| 路径计算超时 | 返回 408 + 建议减少库位数或换算法 |
| 快照回滚冲突 | 加编辑锁后回滚，无锁则拒绝 |
| WebSocket 推送失败 | 记入日志，不影响主业务 |
| 库位状态更新并发 | 乐观锁（update_time 版本号） |

## 8. 与现有低代码平台的关系

- **独立模块**：所有代码在 `com.server.w3d` 包下，不侵入现有 CRUD 引擎
- **独立表**：所有表以 `w3d_` 前缀，不与现有业务表冲突
- **权限**：复用现有 RBAC，通过菜单 + 权限码控制（如 `w3d:view`、`w3d:edit`）
- **认证**：复用现有 JWT/网关认证，API 走网关统一鉴权
- **WebSocket**：独立 WebSocket 端点，与现有 WebSocket（如有）不冲突
- **Redis**：Key 以 `w3d:` 前缀，不与现有缓存 Key 冲突
- **不使用 JdbcTemplate**：遵循现有约束，业务 DML 走 helper（MyBatis-Plus）
