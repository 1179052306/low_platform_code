## 2. 模块A：编码字段属性（base-data 控件）

### 2.1 属性注册（materials/dx-materials.ts）

base-data 控件属性组（现有 refPageId/valueField/displayField 旁）新增：

```ts
{ key: 'codeField', label: '编码字段', type: 'string' }
```

- 类型 string，默认空；**不提供下拉编辑器**——按既有规范（基础资料配置项一律弹窗选择回填，不用下拉框），见 2.2；
- 依赖顺序：先选 refPageId（关联基础资料页面）才能配编码字段，未选 refPageId 时该行置灰并提示"请先选择关联基础资料页面"（与 displayField 的联动行为一致）。

### 2.2 属性面板（components/designer/PropertyPanel.vue :413-490 base-data 属性区）

- 「编码字段」行：显示当前值（只读文本）+「选择」按钮 → 打开**字段选择弹窗**；
- 弹窗复用 displayField 字段选择弹窗组件，模式改为**单选**（displayField 是多选拼接、codeField 必须唯一确定）；
- 弹窗数据源：目标页面（refPageId）的 `lc_field_meta` 字段列表（走现有字段查询 API）；`isUnique=true` 的字段行尾标「（唯一）」引导优先选择；
- 选中后回填 `props.codeField`，行内显示字段名。

### 2.3 保存校验强制（store/designer.ts 保存校验区 :1058-1088 模式）

保存校验数组追加规则：

```
遍历 schema 所有 type=='base-data' 控件：
  refPageId 已配 && codeField 为空
    → 拦截保存，错误信息：
      "控件「{label}」未配置编码字段（数据导入必需），请在属性面板完成配置"
```

错误经 Element Plus 消息组件展示（多条合并，禁止原生 alert）。**表格页/移动端页面同样拦截**（元数据同步在所有保存模式下触发，口径一致）。

### 2.4 旧 schema 兼容

设计器加载 schema 时（解析 normalize 阶段）对存量 base-data 控件自动补 `codeField: ''` 默认值——沿用 openPage 等新增配置项的向后兼容模式，避免旧页面属性面板显示 undefined。

### 2.5 与后端的契约

保存页面时 `props.codeField` 随 schema 存入 `lowcode_page`；后端 `MetaSyncService.extractBaseDataRef` 提取进 `base_data_ref` JSON 新键（后端文档§4.1）。**存量页面必须补配后重新保存**，导入时的报错文案由后端兜底返回。

## 3. 模块B：工具栏导入预设按钮

### 3.1 预设项注册（components/designer/ToolbarItemsEditorDialog.vue）

`PRESET_ITEMS`（:40-85）追加：

```ts
{ name: 'import', caption: '导入', icon: 'upload', location: 'before', visible: true }
```

- `upload` 图标已在 DX_ICONS 列表（:97-107），无需新增；
- `remoteGrid`（表格页面）可用、静态表格隐藏（与 add/edit/delete 的显隐规则一致，:170-175 处的过滤条件追加）。

### 3.2 默认工具栏（materials/dx-materials.ts :478-493）

data-grid 默认 `toolbar.items` 在 export 前追加 `import` 项——表格页默认开启工具栏与增删改按钮的既有偏好下，导入按钮默认可见（属性面板可关）。

### 3.3 运行时行为（components/renderer/RendererNode.vue :534 预设 switch）

```ts
case 'import': {
  // 与 add/edit 同层的预设分发（不走 onClick 沙箱）
  importDialog.open({ bizCode: node.props.tableName, pageTitle: 页面标题 });
  break;
}
```

- `LcTable.handleToolbarClick` 对未知 name 会 `emit('toolbar-item-click')`，预设按钮在 RendererNode 层拦截处理（与现有 add/edit/delete/export 机制完全一致）；
- 导入完成（终态 SUCCESS/PARTIAL）→ `grid.refresh()`（与 add 保存后行为一致）；
- 自定义按钮用户仍可通过 `onClick` 沙箱自行调 `importDialog` API。

## 4. 模块C：ImportDialog 导入弹窗

### 4.1 文件与形态

- 新组件：`src/components/import/ImportDialog.vue`；
- 组件风格随现有弹窗组件（ToolbarItemsEditorDialog 等）保持一致；提供 `open({ bizCode, pageTitle })` 方法 + 组件单例挂载（与 pageModal 管理方式对齐，注册进 RendererNode 可访问的上下文）；
- 布局：`el-dialog`（宽 640px）+ `el-steps` 三步指示 + 内容区；扁平化、卡片无圆角、区块间细边框分隔（系统级 UI 偏好）；弹窗内如需确认框，ElMessageBox 沿用现有 z-index 提升方案。

### 4.2 状态机

```
STEP_TEMPLATE（①下载模板）
  │ 点击"下载模板"→ GET /template → 浏览器另存
  │ 点击"我已填好，上传文件"→
  ▼
STEP_UPLOAD（②上传）
  │ el-upload 手动模式：限 .xlsx、≤20MB、单文件
  │ 超限/格式错 → ElMessage 行内错误（不弹原生 alert）
  │ 确定上传 → POST /execute (multipart)
  ├── 响应 sync:true  → STEP_RESULT（同步完成，直接渲染统计+错误清单）
  └── 响应 sync:false → STEP_PROGRESS（taskId 记住）
STEP_PROGRESS（③执行/排队）
  排队中(RUNNING 前)：显示"排队中，前面还有 N 个任务"（queuePosition）
  执行中：el-progress 百分比 + 文本"已处理 35,000 / 100,000 · 成功 34,980 · 失败 20"
  轮询：GET /task/{taskId}，setTimeout 链式 2s（不用 setInterval 防堆叠）
  终态 → STEP_RESULT；用户可点"取消任务"→ POST /cancel → 终态 CANCELLED
STEP_RESULT
  统计卡：总数/成功/失败（+明细表计数，主从时后端返回）
  失败>0：错误清单表格（行号/列名/原因，vxe-grid 或 el-table，分页 15 条/页）
        +「下载错误文件」按钮（含原始数据+错误原因列）
  按钮：完成（关闭弹窗+ grid.refresh()） / 重新导入（回 STEP_UPLOAD）
```

### 4.3 弹窗关闭与任务恢复

- **关闭弹窗不终止任务**（后端任务独立运行）；一期从简实现"重开恢复"：弹窗 `open()` 时先 `GET /tasks?bizCode=&pageSize=1` 查最新非终态任务，存在则直接进入 STEP_PROGRESS 恢复进度视图；
- 工具栏按钮进行中角标（红点/进度百分比悬浮）为**二期**，依赖跨组件任务状态管理；
- 多标签页场景不做前端互斥（后端表级准入已是唯一事实源，第二个标签页提交会被拒并收到明确错误）。

### 4.4 导入历史

弹窗右上「历史」链接 → 展开当前 bizCode 最近 10 次任务（GET /tasks）：时间/状态/成功失败数/错误文件下载。一期为弹窗内简单列表，不做独立页面。

## 5. 模块D：API 对接层

`src/api/` 新增 `import.ts`（与 gatewayCall 并列，非网关动作，直连 bcd-code 的 /api/lowcode/import/*）：

```ts
downloadImportTemplate(bizCode)            // GET /template → blob → file-saver 另存（file-saver@2.0.5 已有依赖）
executeImport(file, bizCode)               // POST /execute multipart（同步/分流响应联合类型）
getImportTask(taskId)                      // GET /task/{id}
cancelImportTask(taskId)                   // POST /task/{id}/cancel
downloadErrorFile(taskId)                  // GET /task/{id}/errors → blob
listImportTasks(params)                    // GET /tasks
```

- 响应错误（准入拒绝、任务 FAILED 等）统一走现有 axios 拦截器错误提示链路，`errorMsg` 必须透传展示（后端失败透传前端原则）；
- 模板/错误文件下载复用 LcTable 导出已用的 `file-saver` 模式；
- 返回体含雪花主键值时后端已转 String，前端只做字符串展示，无精度问题。

## 6. UI 规范遵循清单（实施时逐项对照）

| 规范 | 落点 |
|---|---|
| 图标文本符号，不用 @element-plus/icons-vue | 上传/下载/关闭等图标 |
| 禁止原生 alert/confirm | 全部 ElMessage / ElMessageBox（错误多条合并展示） |
| 扁平化、无圆角、细边框分区 | 弹窗与结果卡片样式 |
| 弹窗内下拉/确认框 z-index | 沿用 global.css popper 提升 + ElMessageBox customClass 方案 |
| camelCase 命名 | props/事件/API 参数（pageSize、queuePosition…） |
| 表格清单分页 15 条/页 | 错误清单、历史列表 |
| ElDatePicker 类控件不引入 | 本功能无日期选择 |

## 8. 与现有机制的集成边界

- 不改 gatewayCall / LcTable 导出 / enrich 展示链路 / pageModal 机制；
- 导入按钮与 add/edit/delete 同级预设，不做硬编码行为（openPage 配置驱动模式不受影响）；
- ImportDialog 独立于物料体系（非设计器物料），运行时组件归 components/import/；
- 表单整单保存（主从编辑）是独立需求，将来复用后端 MasterDetailWriter，前端另行设计，本文不含。
