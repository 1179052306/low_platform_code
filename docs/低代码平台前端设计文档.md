## 3. 运行时渲染契约（G5 补全）

> 后端 G5 缺口："运行时如何按 Meta 自动渲染列表/表单未定义"。本章补全前端运行时渲染的所有改动点。
> 现有 `RendererNode.vue`（2269 行）是运行时核心，已用 `apiCall` + `CustomStore`（DevExtreme）+ `createSandboxedFunction`。

### 3.1 运行时按合并后 schema 渲染（分层继承配合）

**问题**：分层继承后，运行时应按**合并后 schema** 渲染，而非原始单层 schema。

**方案**：

| 文件 | 改动 | 说明 |
|------|------|------|
| `components/renderer/RendererNode.vue` | 加载页面时先调 `/api/lowcode/meta/merged?pageId=xxx` 获取合并后 schema，再递归渲染 | 现有直接用 `designerStore.schema`，改为运行时走合并接口 |
| `store/designer.ts` | 加 `loadMergedSchema(pageId)` 方法 | 调后端合并接口，返回合并后 PageSchema + 溯源信息 |
| `utils/request.ts` | 无改动 | 合并接口走现有 httpRequest |

**关键代码示意**（`<script setup>` 风格）：
```ts
// RendererNode.vue 内（或 PreviewView.vue 加载时）
import { ref, onMounted } from 'vue'
import { httpRequest, extractPayload } from '@/utils/request'

const mergedSchema = ref<PageSchema | null>(null)

onMounted(async () => {
  // 分层继承后，运行时加载合并后 schema
  const res = await httpRequest('/api/lowcode/meta/merged', {
    method: 'POST',
    body: JSON.stringify({ pageId: designerStore.pageId })
  })
  mergedSchema.value = extractPayload(res)
  // 后续递归渲染用 mergedSchema.value.root 而非 designerStore.schema
})
```

**兼容**：无分层时后端合并接口直接返回该页面 schema（单层等价于合并），前端无感。

**问题**：后端补了 query action，前端列表页/查询页需配合。

**方案**：

| `components/renderer/AdvancedSearchPanel.vue` | 查询条件配置化：从 `PageSchema.queryConfig` 读取可查询字段、操作符、默认值 | 现有手写搜索条件，改为 schema 驱动 |
| `types/schema.ts` | `PageSchema` 加 `queryConfig?: QueryConfig` | 查询配置（可查询字段、默认过滤、排序、分页） |
| `components/designer/QueryConfigDialog.vue` | **新建**，设计器中配置查询条件 | 复用 ColumnEditorDialog 弹窗模式 |
| `store/designer.ts` | 加 `updateQueryConfig()` 方法 | 管理 `PageSchema.queryConfig` |

**QueryConfig 数据结构**：
```ts
export interface QueryConfig {
  fields: QueryFieldConfig[]       // 可查询字段配置
  defaultFilters?: FilterRule[]    // 默认过滤条件
  defaultSort?: SortRule[]         // 默认排序
  pageSize?: number                // 默认分页
}

export interface QueryFieldConfig {
  fieldName: string
  label: string
  operators: string[]              // eq/ne/like/in/between/dateRange...
  required?: boolean
  defaultValue?: unknown
  refBizCode?: string              // 引用类型（下拉选）
}
```

**CustomStore 改造**：
```ts
// RendererNode.vue 内表格数据加载
const dataSource = new CustomStore({
  key: 'id',
  load: async (loadOptions: any) => {
    const result = await apiCall('lowcodeGateway', {
```

**问题**：后端权限要下发前端驱动渲染（字段显隐/只读/必填、列权限、按钮权限）。

**方案**：

| `components/renderer/RendererNode.vue` | 表格列按权限过滤：无列权限的列不显示 | 在 dx-data-grid columns 配置前过滤 |
| `components/renderer/RendererNode.vue` | 按钮按权限过滤：无按钮权限的按钮不显示 | 在操作按钮渲染前过滤 |

**权限元数据结构**：
```ts
export interface PermissionMeta {
  fieldPermissions: Record<string, 'hidden' | 'readonly' | 'editable'>  // fieldName → 权限
  buttonPermissions: Record<string, boolean>                            // buttonCode → 是否可见

}
```

**RendererNode 权限过滤示意**：
```ts
// RendererNode.vue 内渲染前
import { hasFieldPermission } from '@/utils/permission'

const visibleNodes = computed(() => {
  if (!mergedSchema.value) return []
  return mergedSchema.value.root.filter(node => {
    if (!node.fieldName) return true
    const perm = hasFieldPermission(designerStore.pageName, node.fieldName)
    return perm !== 'hidden'
  })
})
```

### 8.2 关键代码示意（`<script setup>` 风格）

```ts
// store/designer.ts 扩展
import { ref } from 'vue'

export const currentLayer = ref<MetaLayer>('CUSTOMER')

export function overrideProp(id: string, prop: string, value: unknown) {
  const node = findNode(designerStore.schema, id)
  if (!node) return
  if (!node.overrideProps) node.overrideProps = {}
  node.overrideProps[prop] = value
  pushHistory()
}

export function restoreProp(id: string, prop: string) {
  const node = findNode(designerStore.schema, id)
  if (!node?.overrideProps) return
  delete node.overrideProps[prop]
  pushHistory()
}

export async function getMergedSchema(): Promise<ComponentSchema[]> {
  const res = await httpRequest('/api/lowcode/meta/merged', {
    method: 'POST',
    body: JSON.stringify({ pageId: designerStore.pageId })
  })
  return extractPayload(res)
}
```

### 25.3 保存冲突（乐观锁）

多人同时编辑同一页面/元数据的冲突处理：

| 场景 | 方案 | 说明 |
|------|------|------|
| 页面 schema 编辑 | `PageSchema` 加 `version` 字段，保存时带 version，后端比对不一致则返回 409 | 现有 PageSchema 已有 version 字段 |
| 元数据编辑 | `lc_meta_registry` 有 version，保存时比对 | 后端处理 |
| 冲突提示 | 前端收到 409 时用 Element Plus 提示"页面已被他人修改，请刷新后重试" | 不自动合并（太复杂），让用户决策 |

**前端改动**：`store/persistence.ts` 的 `savePage()` 加冲突处理：

```ts
export async function savePage() {
  try {
    await httpRequest('/api/lowcode/page', { method: 'POST', body: ... })
  } catch (e: any) {
    if (e.status === 409) {
      ElMessage.error(t('页面已被他人修改，请刷新后重试'))
      throw e
    }
    throw e
  }
}
```

### 25.4 撤销/重做覆盖

| 新增操作 | 是否 pushHistory | 说明 |
|----------|-----------------|------|
| 层切换（setLayer） | **否** | 层切换是视图切换，不是编辑操作 |
| 覆盖属性（overrideProp） | **是** | 编辑操作，可撤销 |
| 恢复属性（restoreProp） | **是** | 编辑操作，可撤销 |
| 新增字段事件规则 | **是** | 编辑操作 |
| 元数据编辑 | **是**（在各自 store 中） | meta/package/workflow store 各自维护撤销栈 |
| 版本回滚 | **否** | 回滚是不可逆操作（回滚后走新版本），不入撤销栈 |
| 审批操作 | **否** | 运行时操作，非设计器编辑 |

**实现**：各新增 store（meta.ts/package.ts/workflow.ts）仿 designerStore 各自维护 `history` 栈 + `pushHistory()` / `undo()` / `redo()`。

#### 26.2.3 权限预校验（前端提前拦截）

```ts
// utils/permission.ts 扩展
import { permissions } from '@/store/auth'

// 操作权限预校验（前端提前拦截，避免无权限请求发到后端再报错）
export function hasActionPermission(bizCode: string, action: string): boolean {
  if (!permissions.value?.actionPermissions) return true // 权限未加载，放行（后端兜底）
  const bizPerm = permissions.value.actionPermissions[bizCode]
  if (!bizPerm) return true // 未配置权限，放行
  return bizPerm[action] === true
}

// 在统一网关调用前预校验
export async function gatewayCall(bizCode: string, action: string, payload: unknown) {
  if (!hasActionPermission(bizCode, action)) {
    throw new Error(t('无权限执行此操作'))
  }
  return apiCall('lowcodeGateway', { bizCode, action, payload })
}
```

### 26.4 小结

## 30. 关键约束（遵循现有规范）

- 弹窗用 Element Plus，**不用浏览器原生 alert/confirm**
- 后端失败必须透传前端展示，保存失败要提示
- 字段名等约束前端输入时校验
- 改代码后跑 `npm run build` 验证（vue-tsc + vite build）
- 命名 camelCase
- 所有新增组件用 **`<script setup lang="ts">`** 风格（非 Options API）
- 所有新增 store 用独立 TS 模块 + ref/reactive（非 Pinia/Vuex）
- 新增视图复用 PageManageView 的列表+编辑模式，不引入新 UI 框架
- 新增弹窗复用 ColumnEditorDialog 的 el-dialog 模式
- 新增 store 复用 designerStore 的模式（含 pushHistory 撤销栈）
- 界面文案全部用 `t('中文')` 包裹（国际化）
- 新增 API 通过 `api/registry.ts` 注册，走 `apiCall(serviceId, params)` 统一调用
- **RendererNode 拆分**：FE-S0 阶段将 RendererNode.vue 拆为 RendererForm/RendererTable/RendererDetail 三个子组件，避免单文件膨胀（后端第 31.4 节前端评审建议）
