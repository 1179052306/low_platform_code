## 配置体系改造（去 Maven @..@ 注入 → Spring Profile 多环境拆分）

### 背景与目标
用户本地调试痛点：勾选 IDEA「将 IDE 构建/运行操作委托给 Maven」→ 改底层模块不重新 install 不生效；取消勾选 → yml 里 `@nacos.username@`、`@server.port@` 等 Maven 过滤占位符不替换，启动失败（Nacos 报错）。目标：去掉 yml 全部 `@..@` 注入，改用业界标准的「主配置 + 环境专属 profile 文件」Spring Profile 机制。

### 试点：bcd-wms-system（已完成）
新结构（src/main/resources/）：
- `bootstrap.yml`：Nacos 默认骨架（debug 兜底），值用 `${NACOS_*:默认值}` 环境变量占位（不设即用当前 Nacos：172.29.241.131:8001 / nacos / Abcd_1101!，discovery ns=lw、config ns=wms）
- `bootstrap-dev.yml` / `bootstrap-test.yml` / `bootstrap-prod.yml`：各环境完整 Nacos 配置（profile 特定文件优先级高于主文件，激活即覆盖）
- `config/application.yml`：公共应用配置 + debug 默认值（port 8005 写死、param.url=http://localhost:8003、删掉残留 `spring.profiles.active: hxh`、app.env/prefix 默认空串）

- `config/application-test.yml` / `application-prod.yml`：port 6004 + env=test/prod

- pom.xml copy-resources includes 补 `**/application-*.yml`、`**/bootstrap-*.yml`（否则环境文件不进外置 config / serviceRelease）

### 关键技术事实
- Maven 过滤定界符是 `@`（根 pom `useDefaultDelimiters=false`），yml 里的 `${..}` 不会被 Maven 碰 → 两套语法可安全共存
- Spring profile 特定文件（application-{p}.yml / bootstrap-{p}.yml）优先级高于同名主文件，激活即整体/按键覆盖
- bootstrap-{profile}.yml 必须放 resources 根（bootstrap context 只搜 classpath:/）；application-{profile}.yml 放 config/ 子目录即可（主上下文搜索含 classpath:/config/）
- 根 pom `<directory>target${prefix}${envName}</directory>`：不激活任何 Maven profile 时产物目录是字面量 `target${prefix}${envName}`（坑，IDEA/命令行都必须激活某个 profile 或用已有 target）
- 无 profile 时 process-resources 也能正常把环境文件拷进产物（第二段 resources filtering=false 无 includes 全拷）

### 验证结果（-Ptest process-resources）
target-test/classes/config/ 含 4 个 application yml；classes/ 根含 4 个 bootstrap yml；application.yml 产物无 @..@、`${app.prefix}${app.env}` 保留给 Spring；application-test.yml = 6004/env=test。✓
