## B 方案落地：WMS 登录链路改造为 Feign + 内部接口

### 背景
用户问 `com.common.http.HttpClientAuthor` 这套用 HttpClient 手写模拟 OAuth2 授权码 4 步流程（/login → /oauth/authorize 申请码 → 模拟点同意 → /oauth/token 换 token）"是否正确"。诊断后给出 3 种方案，用户选 B 方案：auth 暴露内部接口 + Feign 调用，跳过 OAuth2 套娃。

### 根因
- `pom.xml` 四个 Maven profile 的 `param.url` 全是 `http://localhost:8003`，彻底绕过 Nacos 服务发现
- `HttpClientAuthor` 把后端服务当无头浏览器用 HttpClient 维护 cookie 模拟"用户点同意授权"，OAuth2 协议跟"后端代用户登录"场景不匹配
- 56 个 FeignClient 里唯独登录这块手写 HttpClient，跟微服务体系格格不入

### 改造内容（WMS 项目，8 个文件）

   - 接收 username/password/tenant，直接调 `AuthenticationManager.authenticate()` 校验密码

   - 签出的 token 跟 `/oauth/token` 完全一致（同一密钥对 jwt.jks、同一 TokenEnhancer）

三处都改成 `authFeignClient.login(...)` 一行调用，token 结果包装到 AuthorInfo 让后续代码改动最小。

## 服务端口多环境化：子 pom 加同名 profile + yml @server.port@ 占位符

### 背景
用户想让 `bcd-wms-api-client` 服务端口随环境（debug/dev/test/prod）变化，且配置放在**当前服务的 pom** 而不是根 pom。扩展后要求**所有服务**都按此改造（WMS 全量）。

### 机制（Maven profile 子模块继承）
- 根 pom 用 `mvn -P<env>` 激活 profile 后，**所有子模块 pom 里同 id 的 profile 自动激活**（profile propagation）
- 子 pom 各 profile 定义 `<server.port>端口</server.port>`，yml 用 `@server.port@` 占位符，由 Maven 资源过滤注入死值（跟 `@prefix@`/`@envName@` 同一套）
- **端口走 Maven 注入，服务名走运行时占位符 `${app.prefix}${app.env}`**，两套体系
- 关键约束：子 pom profile id 必须与根 pom 完全一致（debug/dev/test/prod），否则不继承激活
- **坑**：profile 未定义 `<server.port>` 时资源过滤会保留字面 `@server.port@` 导致 Spring 启动失败 → 用 B 方案：4 个 profile 全填端口值（默认跟现状一致），要切环境只改对应 profile

### 改动（WMS 全 21 个服务）
- 每个服务 pom.xml `</build>` 后加 `<profiles>` 块（4 个 profile debug/dev/test/prod，id 跟根 pom 一致，各含 `<server.port>当前端口</server.port>`）
- 每个服务 `src/main/resources/config/application.yml` 的 `port: <数字>` 改成 `port: @server.port@`
- bcd-wms-api-client 端口 8023（首个试点，先行验证通过）；其余 20 个服务批量改
- 服务端口清单：api-in 8013 / api-ops 8023 / api-out 8014 / api-stock 8019 / api-system 8008 / api-tms 8006 / api-wcs 8024 / auth 8003 / base 8015 / combox 8010 / gateway 8004 / ifs 8058 / in 8009 / orderflow 7256 / out 8007 / report 8021 / stock 8012 / system 8005 / tms 8011 / websocket 8025 / api-client 8023
- 验证：`mvn -Pdebug process-resources` 后 target/classes/config/application.yml port 正确替换（auth=8003, gateway=8004, api-in=8013）

### 后续扩展
- OMS/YMS 如需同样改造：同构项目可复用同样方案，逐个服务加 profiles + yml 占位符即可
